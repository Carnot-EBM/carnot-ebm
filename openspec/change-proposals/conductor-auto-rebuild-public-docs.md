# Conductor auto-rebuild of public docs at milestone retro

**Status:** Draft change proposal.
**Origin:** User audit 2026-04-26 found `docs/technical-report.html` (served
  to the public at https://carnot-ebm.org via GitHub Pages) was 24 hours
  and ~5 milestones stale relative to its Markdown source. The pre-commit
  hook `tech-report-html-sync` is configured in `.pre-commit-config.yaml`
  but `pre-commit install` had never been run on the conductor's clone, so
  `.git/hooks/pre-commit` doesn't exist and the hook never fires on any
  conductor commit. CI gating (proposed in the same audit) catches the
  drift on PRs but is downstream of the conductor's own commit pipeline.
**Target milestone:** 2026.04.73.
**Priority:** High (public-facing). The technical report is the project's
  primary research-record artifact and the landing page is the first
  impression for anyone arriving at carnot-ebm.org. Stale headline numbers
  on a public page erode credibility.
**Depends on:** nothing — `scripts/build_technical_report.py` already
  exists and is idempotent.

## Summary

The conductor commits documents at three points:

  1. After each experiment commit — Haiku/in-process doc reconciliation
     edits `_bmad/traceability.md`, `ops/changelog.md`, sometimes
     `docs/technical-report.md`.
  2. After the operational retrospective for a milestone — Sonnet rewrites
     larger sections of `docs/technical-report.md`, `README.md`, and
     `_bmad/*` to reflect the closed milestone.
  3. After the planner emits `research-roadmap-next.yaml`.

Step 2 is the high-leverage one. When the retro Sonnet edits the
technical-report Markdown, the corresponding HTML rendering must be
regenerated *in the same commit* so GitHub Pages' carnot-ebm.org never
serves stale content. The pre-commit hook was supposed to do this; for
operator-clone reasons it doesn't.

The fix: have the conductor itself call `build_technical_report.py`
during its retrospective flow, before staging the commit. Same pattern
as the existing `git_has_changes` sweep in `_archive_current_milestone`.

## What this proposal IS NOT

- **Not a replacement for the pre-commit hook.** Humans editing the
  Markdown locally should still get the HTML auto-regenerated by the
  hook. This proposal adds a parallel path for the conductor's
  non-interactive commits.
- **Not a CI replacement.** The companion CI gate (`tech-report-sync`
  job in `.github/workflows/ci.yml`, just shipped) catches drift on
  PRs and external pushes. This proposal closes the conductor-side
  gap so CI never has reason to fire on a conductor commit.
- **Not an extension to other docs.** README and the landing page
  (`docs/index.html`) are kept current by the conductor's existing
  edit logic. Only the Markdown→HTML rendering of the technical report
  needs the build step.

## Proposed experiments

### Exp A — Wire `build_technical_report.py` into the conductor retro flow

**Deliverable:**
edits to `scripts/research_conductor.py` in two places:

  1. Inside the operational-retrospective block (after the Sonnet
     retro Claude Code call returns successfully and before the
     `git_commit_and_push` call) — call
     `subprocess.run(["python3", "scripts/build_technical_report.py"])`.
  2. Inside the per-experiment doc-reconciliation block — same call,
     guarded by a check that `docs/technical-report.md` was actually
     touched in this iteration (avoid spending CPU on a no-op rebuild).

`tests/python/test_conductor_tech_report_sync.py` — unit test that mocks
the build script, runs the retro path with a touched `.md`, and asserts
the build was invoked and the resulting `.html` was staged.

`results/experiment_<N>_conductor_doc_sync.json`.

**What it does:**

```python
# After retro Sonnet returns, before commit:
md_path = PROJECT_ROOT / "docs" / "technical-report.md"
html_path = PROJECT_ROOT / "docs" / "technical-report.html"
md_changed = (
    md_path.exists()
    and run_cmd(["git", "diff", "--quiet", "--", str(md_path)]).returncode != 0
)
if md_changed:
    rc, _, err = run_cmd(["python3", "scripts/build_technical_report.py"])
    if rc == 0:
        run_cmd(["git", "add", "--", str(html_path)])
        logger.info("Regenerated technical-report.html for milestone retro commit")
    else:
        logger.warning(
            "build_technical_report.py failed (%s) — committing MD-only; CI will catch drift",
            err.strip()[:200],
        )
```

**Acceptance:** After `_archive_current_milestone()` commits the retro,
`git diff` between the MD and HTML shows zero structural drift (HTML's
`<article>` content matches the Markdown render). Verified by the
existing `--check` mode in the build script.

### Exp B — Conductor self-tests `pre-commit install` on startup

**Deliverable:**
edits to `scripts/research_conductor.py` startup block (around the
`EnvironmentAutoFix` apply) +
`tests/python/test_conductor_precommit_check.py`.

**What it does:**

At conductor startup, check whether `.git/hooks/pre-commit` exists.
If not, log a clear warning that the pre-commit hook chain (which
includes `tech-report-html-sync`) is inactive, and offer to install
it via `pre-commit install`.

```python
hooks_pre_commit = PROJECT_ROOT / ".git" / "hooks" / "pre-commit"
if not hooks_pre_commit.exists() and (PROJECT_ROOT / ".pre-commit-config.yaml").exists():
    logger.warning(
        "pre-commit hooks not installed — tech-report-html-sync and other "
        "config'd hooks will not fire on conductor commits. "
        "Run `pre-commit install` from this repo to activate them. "
        "The conductor will continue with its own auto-rebuild as a fallback "
        "(see Exp A)."
    )
```

The conductor does NOT auto-install the hook (would silently change
operator's clone state). It just warns.

**Acceptance:** Conductor logs the warning on startup if hooks are
absent. No behaviour change otherwise. The CI gate + Exp A's auto-
rebuild mean missing hooks no longer cause public-doc drift, but
the warning gives operators a clear nudge to fix their environment.

## Decentralization implications

- **Rule 1 (local-first):** unaffected. `build_technical_report.py`
  uses only the `markdown` Python package (already in the project's
  dev dependencies); no external services.
- **Rule 3 (distribution mirroring):** GitHub Pages is one
  distribution channel for the technical report. The IPFS mirror
  (Exp 934) gives a second channel. Both should serve the same HTML;
  this proposal ensures both serve the *current* HTML.
- **Rule 7 (no vendor abstractions):** the build is a stdlib +
  markdown call; no GitHub-specific hooks.

## Why this is in change-proposals, not just a code change

Three independent surfaces have to stay in sync (`pre-commit`,
the conductor's commit pipeline, CI). Documenting the
interaction-of-three-paths matters more than the code diff. Future
Claude needs to find the rationale for "why does the conductor do
its own HTML build when there's already a hook?" without re-deriving
the audit results.

## Risks

- **Build script becomes a hot path.** Currently runs in <1 sec on
  the 182 KB MD file. If the technical report grows to 5 MB the
  build cost becomes meaningful but still negligible compared to the
  retro Sonnet call.
- **Build failure blocks the retro commit.** Mitigation: the
  proposal logs a warning and commits MD-only on build failure;
  CI catches it on the next push. The conductor never wedges on a
  doc-rebuild error.
- **Conductor's rebuild masks the missing hook.** If Exp A works
  perfectly, operators will never notice their hook is missing.
  Mitigation: Exp B's startup warning makes the missing hook
  visible without depending on it firing.

## Acceptance criteria (overall)

1. `docs/technical-report.html` is regenerated by the conductor
   immediately after each milestone-retro `.md` edit, in the same
   commit. CI's `tech-report-sync` job stays green on every conductor
   push.
2. The conductor logs a clear startup warning when pre-commit hooks
   are not installed.
3. No regression in milestone retro wall-time (build adds <1 sec).
4. The companion CI gate fires only on legitimate drift — operator
   commits with hooks active, or external PRs that bypass the local
   tooling.
