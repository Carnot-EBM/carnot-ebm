## The Three Largest Gaps to the PRD Vision

### Gap 1: exact verification does not yet improve authentic actions

FR12 requires an external constraint layer that changes behavior and retains exact authority.
The authentic fixed-point intervention failed. Carnot has exact checkers and real outputs, but it
does not yet have a priority-preserving action arbiter that protects hard obligations while keeping
useful progress.

### Gap 2: continuous self-learning is causal but not yet authentic or portable

FR11 now has byte-replayable causal evidence. That evidence comes from a frozen synthetic
opportunity stream. Carnot has not shown that an inspectable learner can improve routes on authentic
mandated-GGUF proposals, preserve future reachable support, and transfer across model families.

### Gap 3: shipped live ARC mechanisms lack decision-grade receipts

The trace supervisor, window-120 shadow mode, selfparse tool-gap capture, and tool loop exist. The
window-120 run blocked on GPU ownership. The tool-gap task then gate-blocked, and the
actions-to-progress and adoption tasks never ran. The live agent still needs exact post-action
outcomes, process-isolated controls, durable checkpoints, and an independent reducer.

## Research Delta

Recent work suggests one coherent pivot.

- CEDAR represents persistent action constraints as deterministic automata. This gives Carnot a
  stable object to compose, execute, and audit.
- xTRUCE separates hard feasibility, binding operator rules, and relaxable targets. This gives
  Carnot a safe priority order and conflict certificates.
- PLVR learns inspectable typed programs outside model weights. This gives Carnot a Tier-2
  self-learning target that can reuse the audited transaction store.
- Constraint-weakening results require typed prerequisite, authority, fallback, and consequence
  fields. A prose handoff is not enough.
- Verifier-induced support reshaping requires a future-support gate. A current win that destroys
  later reachable success must roll back.

V594 therefore retires the real-output fixed-point repair branch. It does not tune another text
score. It moves exact constraints to the structured action boundary, learns only an external typed
route program, and then tests the same contract on the live ARC path.

## Phase 1: Typed Obligation and Priority-Arbiter Contract

### Exp6802: Typed operational-obligation automaton v2

Upgrade the existing game-blind trace automaton instead of creating a parallel supervisor. Add a
v2 typed obligation record with prerequisite, authority, fallback, consequence, and one of three
priority tiers. Compile records to a deterministic event automaton and an exact lexicographic
energy. Use frozen, source-free event traces plus adversarial mutations. Prove deterministic
serialization, composition, replay, and fail-closed behavior. This task addresses the earlier
trace-automaton and held-family supervisor failures without claiming a live benefit.

**Deliverable:** `results/experiment_6802_operational_obligation_automaton_v2.json`

### Exp6803: Three-model operational-handoff proposal corpus

Invoke all three mandated local GGUF families. Generate paired structured action proposals under a
direct typed handoff and a length-matched prose-compression handoff. Freeze prompts, model files,
token budgets, seeds, raw bytes, and exact obligation checks. Measure operational preservation,
hard violations, parse completion, proposal diversity, and retry demand per model and scenario.
This is authentic model-output evidence. It is not a live game solve.

**Deliverable:** `results/experiment_6803_sota_operational_handoff_corpus.json`

### Exp6804: Priority arbiter versus flat reject-and-retry A/B

Use the frozen Exp6803 proposals. Compare the v2 lexicographic arbiter with a parameter- and
candidate-budget-matched flat reject-and-retry control. Keep the exact transition simulator outside
both arms. Measure protected hard obligations, accepted progress, retries, candidate use, conflict
certificate completeness, latency, and harmful selections. Completion does not require a positive
effect.

**Deliverable:** `results/experiment_6804_priority_arbiter_ab.json`

### Exp6805: Independent priority-arbiter authority audit

Reparse raw proposal bytes and rebuild the automaton in a fresh module. Recompute every A/B
headline from rows. Attack priority inversion, stale prerequisites, wrong authority, missing
fallback, consequence deletion, model-label leakage, and exact-outcome leakage. The audit must
separate safety from utility and must preserve null results.

**Deliverable:** `results/experiment_6805_priority_arbiter_cold_audit.json`

## Phase 2: Continuous Self-Learning on Authentic Receipts

### Exp6806: Chronological typed route-program stream

Convert Exp6803 and Exp6804 receipts into a chronological program-learning stream. Each event has
a sealed future outcome, a typed primitive set, exact contract verdicts, model-family identity, and
a transaction opportunity. Freeze development, held-future, and leave-one-model-family-out splits.
The stream must have headroom, legal alternative routes, and both admissible and rejected writes.

**Deliverable:** `results/experiment_6806_typed_route_program_stream.json`

### Exp6807: Transactional symbolic route learning A/B

Implement continuous self-learning as an external typed route program. Update only after an exact
receipt. Compare online symbolic-backprop search with frozen, type-only uniform search, and random
valid-update controls at equal capacity and search budget. Store canonical parent and new bytes for
every write. Credit only later changed actions with exact utility witnesses. Roll back current gains
that reduce held-future reachable support.

**Deliverable:** `results/experiment_6807_transactional_route_program_ab.json`

### Exp6808: Leave-one-model-family-out route portability

Freeze the Exp6807 method. Learn from two mandated model families and evaluate on the third, then
rotate the held family. Do not refit on held-family outcomes. Compare the typed program with frozen
and type-only controls. Measure exact utility, reachable best-at-k support, hard-case transfer,
constraint preservation, and program-size cost for every family and order.

**Deliverable:** `results/experiment_6808_route_program_portability.json`

### Exp6809: Independent byte, support, and rollback audit

Cold-replay every Exp6807 transaction and every Exp6808 portability row. Remove each credited write
and disable its later read. Recompute action and utility effects. Attack poison, stale parents,
cross-family labels, future receipts, capacity pressure, and restart boundaries. Require exact byte
and action identity after restart and rollback.

**Deliverable:** `results/experiment_6809_route_program_cold_audit.json`

### Exp6810: Window-120 obligation-supervisor live accrual

**Deliverable:** `results/experiment_6810_arc_obligation_supervisor_accrual.json`

### Exp6811: Live selfparse tool-gap obligation transport

Run one production selfparse cell and a typed canary after Exp6810 transport is ready. Prove that
tool-gap events retain all four operational fields through live serialization, analyzer ingestion,
and refinement-ledger update. Default-off behavior must remain unchanged. The event list may be
empty, but the schema and end-to-end path may not be absent.

**Deliverable:** `results/experiment_6811_arc_tool_gap_obligation_transport.json`

### Exp6812: Obligation-routed actions-to-progress A/B

Run matched live control and treatment cells. The control process must have the tool loop truly
unset. The treatment uses selfparse plus the audited priority arbiter. Match games, seeds, action
budgets, model, token limits, and censoring rules. Measure actions to level progress, progress rate,
restricted mean actions, harmful regressions, and exact hard-obligation violations. Do not claim a
new solve unless the live agent exceeds the registry precheck from its own attempts.

**Deliverable:** `results/experiment_6812_arc_obligation_actions_to_progress_ab.json`

### Exp6813: Independent ARC adoption audit

Use fresh reducers to replay Exp6810-Exp6812 rows and receipts. Verify process isolation, exact
post-action outcomes, source prohibition, solve provenance, ledger updates, and protected files.
Issue one closed decision for the obligation supervisor, tool-gap transport, and selfparse loop:
adopt, narrow, retire, or blocked.

**Deliverable:** `results/experiment_6813_arc_obligation_adoption_audit.json`

## Acceptance Rules

- Every task writes its declared artifact on success, null, block, disqualification, or partial
  completion.
- Every comparative task emits one per-unit row for every arm, seed, model, scenario, order, game,
  or condition needed to recompute the claim.
- Every artifact carries the closed `verdict_class` enum next to `honest_verdict`.
- Every `blocked_*` verdict names the exact failed check and observed value in
  `gate_check_summary`.
- Every task that invokes an LLM declares at least one mandated GGUF in `MODEL_SPECS`. Exp6803 uses
  all three. Exp6810-Exp6812 use the production Qwen3.6 flagship MoE.
- The legacy small models may run CPU smoke tests only. Their rows cannot support a headline.
- Exact validators remain external release authorities. A learned score, route program, or model
  vote may not certify itself.
- Live ARC rows must record `solve_provenance`. Only `live_agent_self_discovery` can support a live
  level claim. Development proxies and outer-loop reverse engineering cannot.
- No task reads game source, runs offline ground-truth BFS, adds a hand-built per-game adapter, or
  re-solves a registry-complete level.
- Prior blocked or null scopes carry explicit `prior_failures` entries. The same verdict retires the
  repeated scope.

## Milestone Exit

V594 succeeds as a research milestone when all 13 tasks have terminal artifacts and Exp6814 gives
closed branch decisions. A positive product claim additionally requires one of these row-derived,
cold-audited outcomes:

1. the priority arbiter preserves every hard obligation and improves accepted progress or retry cost
   over the matched control;
2. the typed route program improves held-future exact utility without shrinking reachable support
   and survives byte, poison, restart, rollback, and cross-model audits; or
3. the live ARC treatment improves actions-to-progress without hard-obligation harm under
   `live_agent_self_discovery` provenance.

A clean null or a well-diagnosed resource block remains valid evidence. It narrows or retires the
branch instead of being converted into a positive claim.
