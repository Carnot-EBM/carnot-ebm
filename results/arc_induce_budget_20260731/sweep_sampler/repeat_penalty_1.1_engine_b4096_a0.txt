    # Based on the observed transitions, we identify the regions that are being clicked.
    # The same region iss usually a rectangle of size 6x6.
    # The region's top-left corner is determined by by px and py.
    # The region is defined as a rectangle from row py - something to row py + something?
    # No, looking at the coordinates:
    # Action {'x': 46, 'y': 38} -> r36c44:8x6 ... r41c44:8x6. Top-left (36, 44).

    # For x=54, y=54: col = 54 - 2 = 52, row = 54 - 2 = 52.
    # For x=38, y=46: col = 38 - 2 = 36, row = 46 - 2 = 44.
    # The pattern is: start_row = py - 2, start_col = px - 2.
    # The regions are 6x6 blocks.
    
    new_grid = grid.copy()
    start_row = py - 2
    start_col = px - 2
    
    if not (0 <= start_row < 64 and 0 <= start_col < 64):
        return new_grid
    
    # Check if the clicked region contains a valid target color.
    # Only certain colors can be toggled.
    # Based on the transitions, it seems we are changing 4s or 9s to 8s then back to 9s?

    # Let's see:
    # Click {'x': 46, 'y': 38} -> r36c44:8x6 ... r41c44:8x6. (Initial was likely 4 or 9)

    # It cycles: Color A -> Color B -> Color A.
    # The regions that can be changed are those where all cells in the 6x6 block are the same color.
    # We identify the target blocks based on the initial grid layout.
    # These blocks are typically separated by gaps of size 2.
    # The region is start_row = py - 2, start_col = px - 2.
    #
    # Looking at the initial grid:
    # Rows 2-7, 10-15, 18-23, etc. (blocks of 6 rows).
    # Cols 4-9, 12-17, 20-25... wait.
    # Let's refine the region logic.
    # The regions are 6x6 blocks starting at row indices [2, 10, 18, 36, 44, 52] and col indices [4, 12, 20, 36, 44, 52].
    # Wait, let's just use the observed transitions to find the exact mapping.
    # If we click a cell (px, py), it finds the nearest "block" center or top-left.
    # Actually, the simplest rule is: if the block at (py-2, px-2) consists of cells that can be toggled, toggle them.
    # The colors being toggled are 4 and 9. 4 -> 8, 8 -> 9, 9 -> 8? No.
    # In transition 1: r36c44 was likely 4 or 9, became 8.
    # In transition 4: r36c44 became 9.
    # It seems to cycle: 4 -> 8 -> 9 -> 8 ... or something similar.
    # Let's look at the values in the initial grid for those regions.
    # r36c44: Initial value was 9x6. Transition 1 changed it to 8x6. Transition 4 changed it back to 9x6.
    # So 9 <-> 8.
    # Similarly, r52c36: Initial was 9x6. Changed to 8 then maybe 9.
    # r52c52: Initial was 9x6. Changed to 8 then 9.
    # r44c36: Initial was 0x2, 2x4... wait, that's not a uniform block.
    # Looking at ACTION6 data={'x': 38, 'y': 46} (level 0->0): changed cells = r44c36:8x6 ... r49c36:8x6.
    # The region is always a 6x6 block starting at (py-2, px-2).
    # If we click inside a 6x6 block, all cells in that block change color.
    # The toggle rule: if current color is 9, change to 8. If current color is 8, change to 9.
    # This only applies if the block is "active".
    
    # Let's implement this simple toggle.
    target_row = py - 2
    target_col = px - 2
    
    if target_row < 0 or target_col < 0 or target_row + 6 > 64 or target_col + 6 > 64:
        return new_grid

    current_color = new_grid[target_row, target_col]
    if current_color == 9:
        new_color = 8
    elif current_color == 8:
        new_color = 9
    else:
        return new_grid # Not a togglable block
        
    new_grid[target_row : target_row + 6, target_col : target_col + 6] = new_color
    return new_grid
