# Adversarial code review synthesis: Carnot ARC-AGI-3 live agent

Six review lenses produced 40 adversarially-checked findings: **39 confirmed, 1 uncertain, 0 refuted**. After deduplication (the dead early-stop flag was independently found by four lenses; the frontier BFS, uncached frontier keys, budget-estimator recompute, and SGE-router port drift by two to three each) the confirmed set reduces to 30 entries. No single finding rated critical; the closest thing to critical is the *interaction* of three majors — the dead early-stop flag, the 5x action-budget raise it was supposed to safeguard, and the once-per-level induction latch — which together reshape the scored run's wall-clock profile in ways none of the underlying sweeps measured.

Terminology: the "scored path" is the default configuration the Kaggle submission actually runs (as opposed to env-gated experiment arms); "induction" is the tier where the agent asks its local LLM to write an executable world model for the current game; the "frontier" is the explorer's set of known-but-not-fully-exhausted states.

## Correctness

### Major

1. **`arc_competition_agent.py:6072-6076` (also 6061, 5101-5102) — Plan execution is fully open-loop despite the class contract "on divergence, back to EXPLORE."** No divergence check exists anywhere; `self._prev` is nulled at induce time and never re-set during execute, so executed plan steps produce no Transition rows and the agent learns nothing from them. Corollary: a plan-won level records a stale pre-plan explore row as `_win_transition` under a comment asserting the opposite. A wrong 30-step plan burns 30 blind actions, and (per finding 5 below) induction cannot re-fire to use what should have been learned. Fix: set `self._prev` per plan step so the existing transition-collection block captures outcomes; compare observed vs predicted state and break to explore on mismatch; capture the win transition from the actual last emitted action.

2. **`arc_competition_agent.py:6062-6067` (plans from `root_grid` at 6244/6275/6398/6975; gate at 5169-5173) — Level-up reinduction plans are computed from the level's opening grid but executed from the current displaced state with no RESET.** The gate requires at least one post-boundary transition, so by construction the agent has already moved when `_execute_plan_from_current=True` replays a plan valid only from the opening grid — wrong from step 0, then executed open-loop per finding 1. This is the default-ON scored path for every post-level-1 planned attempt whose pre-induction explore actions changed state (the common case). Fix: plan from the actual current grid (`self.transitions[-1].next_grid`) when executing from current, reserving `root_grid` for the RESET-replay path.

3. **`arc_competition_agent.py:3302-3309` (latch at 4260-4263, ended at 4357) — The online-discriminator frontier prune has no never-empty floor, and `explored_out` is a one-way latch.** A logistic discriminator fittable from as few as 6 samples can transiently score every open node below the 0.12 threshold; `_frontier` then returns None, `explored_out` latches True (assigned only at init and there), and the game ends with most of the 2000-action budget unspent, reading as a legitimate "fully explored" null. The codebase's own hazard pruner documents and guards exactly this class ("NEVER-EMPTY GUARD, load-bearing"); this older prune path lacks it. Fix: retain the single highest-scoring node when the prune would empty the frontier, and count the event in diagnostics.

4. **`arc_executable_world_model.py:6085-6096` (stop() at 6712-6715) — `_ensure_server` leaks a still-loading llama-server child on wait exhaustion.** On timeout it returns failure leaving the child running and referenced; the next call finds the server unhealthy, skips reuse, and Popens a second child on the same port, overwriting `self._proc` — so `stop()` can only ever reach the newest child and the orphan (eventually holding ~20 GB VRAM) becomes unreachable by any cleanup path. This is the default-ON scored generator path. Fix: before Popen, poll/terminate an existing live child; on wait exhaustion terminate or at least record the leak in server-failure diagnostics.
   - *Sibling (minor):* `_ensure_server` is also an unsynchronized check-then-spawn across all per-game swarm threads (`:5920-5944`, no lock anywhere in the module). Because llama-server binds its port before model load, losers die cheaply at bind, so the realistic cost is a few doomed spawns plus misleading MTP-verification evidence (each loser greps its own dead process's log), not concurrent VRAM loads. Fix: a module-level double-checked lock around the unhealthy-to-Popen section.

5. **`arc_executable_world_model.py:3735` (consumers at 4910 and `scripts/kaggle/submission_kernel/main.py:434-441`) — The shared-context-pool admission arithmetic is sized against a stale worst-case prompt measurement.** `_INDUCE_WORST_CASE_PROMPT_TOKENS = 15767` was measured 2026-07-28 at k=8 with no object table; since then k defaults to ALL transitions (2026-08-01) and the object-structure block is default ON (2026-08-07, up to two 60-row tables), while the pool leaves only ~617 tokens of per-slot margin — the code's own docstring records that 854 tokens over produced 4/4 HTTP 500s. The kernel's concurrency probe trims its synthetic prompt to the same stale constant, so preflight prints "LLM CONCURRENCY OK" for a configuration the real agent can exceed on dense 64x64 games — green-while-broken in the diagnostic itself. Fix: re-measure the worst case under current defaults through the tokenizer; cap the objects/transitions blocks by token budget, not row count.

### Minor (all confirmed; each in a default-OFF or opt-in path, so they corrupt experiment arms rather than the scored run)

- **`arc_competition_agent.py:5052-5058, 5200-5323` — The "win-state exemplar" is provably the current level's opening board, so the graded goal bias (`CARNOT_ARC_GRADED_GOAL_BIAS=1`) is an inverted gradient** pulling search back toward the start state; any A/B of the lever measures an anti-gradient and will retire it for the wrong reason. Fix: derive the exemplar from the last pre-win board, or gate the graded branch off until a real exemplar exists.
- **`arc_competition_agent.py:6124-6158, 5412` — pi/plan bookkeeping asymmetry under `CARNOT_ARC_ACTIVE_PROBE=1`:** post-probe reinduction either silently skips a new plan's first step (stale pi=1) or raises an uncaught IndexError on the stale one-step probe plan. Fix: reset plan/pi at `_induce_and_plan` entry and bounds-guard the induce branch.
- **`arc_competition_agent.py:5120-5131, 6333-6361` + `arc_solver_kit.py:6161-6180` — Trajectory transfer's input is not a replayable trace** (full multi-branch explore history with RESETs structurally absent, OOB clicks dropped mid-sequence, confidence gate blind to linearity, and a multi-level burst overwrites the trace with an empty list). Fix: capture the trace from the winning node's graph path; require `oob_dropped==0` and sane length in the gate.
- **`arc_executable_world_model.py:6451-6455 vs 5625-5645` — The chat-completions route silently drops `repeat_penalty`/`repeat_last_n`,** so the think-mode A/B arm differs from control in two dimensions (think AND no repetition-loop mitigation). Fix: thread the penalty fields through `_chat_complete_request`.
- **`arc_executable_world_model.py:6877-6879, 6795-6796` — Think-mode routing is incomplete:** the split-induce fallback and goal-only prompt append the reasoning-suppressing pre-opened fence unconditionally, so two of three induce prompt shapes never actually think, diluting the treatment arm toward control. Fix: gate the fence on `not induce_think_on()`, mirroring the combined call.
- **`arc_executable_world_model.py:6394-6401, 6471-6480` — `use_chat_template=True` plus the default-ON codeonly path is structurally broken:** fence-primed prompt through a chat template with `stop=["```"]` armed truncates at the first backtick fence the model emits. Fix: make `_codeonly` and `use_chat_template` mutually exclusive, as `_think_on` already is.
- **`arc_competition_agent.py:3254-3271` + `arc_hud_bar_detector.py:650-658` — The budget-meter feed never segments at level boundaries:** the resegmentation rule needs a full byte-match of the masked region, which a changed level/score counter permanently defeats, biasing `fill_fraction` across levels (softened by the windowed-fit None period right after the boundary; flag default OFF). Fix: append the explicit None marker to `_budget_frames` on level-up.

## Speed

### Major

1. **`arc_competition_agent.py:3368 -> 3430-3458` (shipped ON via `SUBMITTED_NAVIGATION_COST_TIEBREAK=True`; confirmed by two lenses) — `_frontier` runs a fresh from-scratch BFS over the whole known graph for every eligible node on every call,** materializing a path copy per enqueued node, then `next_move:4285` re-BFSes the winner; the sibling `_partial_forward_path` (3599-3625) repeats the shape with up to depth-45 independent BFS runs from the same source, firing its BFS even for ancestors that cannot improve the current best. All BFS runs share one source (`self.cur`), so one distance-map BFS per call is exactly equivalent and ~V times cheaper — the in-file precedent (`_gradient_frontier_target`, "one multi-source reverse BFS") already exists. Cost grows roughly quadratically-to-cubically with the 400->2000 action-budget raise; sized for 400, unmeasured at 2000.

2. **`arc_competition_agent.py:3312-3321` (via 2084-2098 and 2057-2075; both components shipped ON; confirmed by two lenses) — Every `_frontier` call recomputes, per node, two expensive keys over immutable inputs:** the action-effect prior scores every remaining untested candidate (~34-55/node) through the frame-change scorer (with a per-candidate SHA-1 plus grid conversion even on CNN-cache hits), and the goal-bias energy re-runs on the node's stored frame (post-induction, an exec'd Python predicate per node per call). The adjacent value head documents this exact bug class and its frame-hash-cache fix — applied to value only. Fix: memoize per `(node_hash, untested-length)` and per `(node_hash, goal_bias generation)`; batch the candidate scorer per frame.

### Minor

- **`arc_competition_agent.py:3263-3267` + `arc_hud_bar_detector.py:715` — With `CARNOT_ARC_BUDGET_AWARE_SEARCH=1`, the budget estimator re-runs full-history Stage-2 analysis every action** (evidence kwarg ignored, previous-frame signatures recomputed in-loop, frames re-prepared twice): O(actions^2) numpy work that will poison the very A/B the wiring exists for. Default OFF. The companion default-path memory worry is largely moot — the competition framework retains all frames anyway. Fix: stream the segment state incrementally, or at minimum pass `evidence=`.
- **`arc_competition_agent.py:1752-1781` + `arc_value_learner.py:1396-1416` — The online discriminator refits from scratch (zeros, 120 full-batch iterations over all history) every 4th sample forever,** O(N^2) total with sample count tracking node count. Seconds per game today; grows quadratically with any future budget raise. Fix: warm-start with ~10-20 iterations and scale `refit_every` with N.
- **`arc_competition_agent.py:3284, 3287` + `arc_frontier_discipline.py:408-440` — On click games the tier barrier makes two O(sum-of-untested) passes per `_frontier` call** over data that changes by one popped row per action (both passes short-circuit, so this is a constant-factor add-on to the two majors above). Fix: incremental per-node min-open-tier and per-tier counters.

## Gaps

### Major

1. **`arc_competition_agent.py:160` vs `:1140` and `:4744-4803` (confirmed independently by four lenses) — `SUBMITTED_EARLY_STOP_GRACE = 400`, commented "Enabled 2026-08-07," is dead code:** the constant is read nowhere; `E3AgentPolicy` neither accepts nor forwards it, the explorer default stays None, and it is absent from `SUBMITTED_AGENT_CONFIG` so the parity test cannot catch the drift — the exact "SILENT NO-OP" the project's own spec and sweep scripts warned about, and `analyze_arc_early_stop_sweep.py:289` now asserts the opposite of reality. Every scored game that banks its last reachable level runs its fruitless tail to the full 2000 actions (5x the old cap) while the record claims the wall-clock safeguard is on. Fix: thread it through `E3AgentPolicy.__init__` into the explorer, pin it in `SUBMITTED_AGENT_CONFIG`, and correct the comment and the stale sweep assertion.

2. **`arc_competition_agent.py:5174, 6056-6057` — LLM induction fires at most once per level on the scored path:** `self.induced` latches and resets only at a level boundary or under the env-gated active probe, so after one refused induction (the measured modal outcome) the remaining ~1900 actions accumulate exactly the transition evidence a second attempt would need while the LLM tier is structurally unreachable. The 400->2000 raise that multiplied this cost 5x was justified by an LLM-off sweep, so the interaction was never measured. Fix: bounded re-induction on renewed stall (reset the latch after N new transitions, capped K attempts), or at minimum record "tier latched off" in the liveness witness.

3. **`arc_competition_agent.py:1064-1088` + `arc_frame_change_predictor.py:493-519` — Declared-ON search components (candidate router, frame-change scorer, and therefore the action-effect prior) degrade to None through bare `except Exception` fallbacks with no counter, no stderr line, and no witness field,** while `SUBMITTED_AGENT_CONFIG` declares them enabled. A missing checkpoint or failed import on the Kaggle read-only mount silently ships an unrouted, unranked agent whose every artifact describes the fully-routed one — the same green-while-broken shape as the 0.08 incident. Fix: record load outcomes (`*_loaded` booleans plus the swallowed repr) in the generator-liveness witness; print one greppable line per fallback.

4. **`scripts/kaggle/submission_kernel/main.py:614-620, 630` — The swarm subprocess timeout equals the full 12h Kaggle cap with zero margin, `TimeoutExpired` is uncaught, the return code is never inspected, and the kernel unconditionally prints "complete"** — so a run that dies at the deadline ends as a hard kill or traceback, and a swarm that crashed at t=0 is indistinguishable from success by the terminal log line. Fix: ~41000s timeout with try/except, and print `SWARM EXITED rc=N after Ns`.

5. **`arc_competition_agent.py:7543-7552` — `MAX_ACTIONS = 2000` shipped at double the budget sweep's own ~1000 worst-case-safe ceiling on an admittedly unconfirmed 16 GiB host-RAM assumption,** with no memory or wall-clock backstop (the grace that would bound the tail is dead per gap 1) and no host-RAM print in the kernel preflight. Fix: print `/proc/meminfo MemTotal` next to the nvidia-smi preflight; until confirmed, drop toward the safe ceiling or wire the grace.

6. **`scripts/kaggle/submission_kernel/main.py:96` — The agent-code self-locate is a bare `next()` over an rglob:** a missing dataset or re-laid-out upload raises a message-free StopIteration at import time, killing the run before any game while the kernel still prints "complete" — unlike the loudly-guarded llama-server resolution 20 lines below. (One lens sub-claim was corrected: `parents[2]` is anchored by the glob pattern, so mount-nesting changes are harmless; the trigger is the dataset missing or internally restructured.) Fix: list() the hits and print a loud attach-the-dataset line before raising.

7. **`arc_executable_world_model.py:6075-6081` — The agent's llama-server stderr — the only discriminator between recoverable context overflow ("mode A") and server death via `ggml_abort` ("mode B," explicitly still open) — lands in `/tmp` inside the ephemeral Kaggle container** because the kernel never sets `CARNOT_ARC_SERVER_LOG_DIR`, while carefully capturing the probe's stderr to `/kaggle/working`. A mid-eval generator death would again be undiagnosable, one hop downstream of where that logging chain was built. Fix: `setdefault` the log dir to `/kaggle/working` in the kernel; print the stderr tail when `n_server_failures > 0`.

## What this review did not cover

This was a static, read-only review: no tests were executed, no profiler was attached, and no live or scored run was measured, so every frequency and magnitude claim above (the BFS blowup arithmetic, the discriminative-prune trigger probability, the context-pool overflow rate, host-RAM headroom) is a structural inference from code, comments, and the project's own recorded sweeps rather than an observation. Three confirmed findings would repay measured follow-up most: (1) profile one 2000-action click-heavy game to size the `_frontier` hot loop (per-node BFS plus uncached keys) — this decides whether the two Speed majors actually dominate the shared 12h envelope or merely scale poorly; (2) tokenize one worst-case induce prompt under the current defaults (k=all, object table on) to replace the stale 15767 constant — minutes of work that directly settles whether the scored LLM tier can overflow its context slot while preflight reports healthy; (3) one instrumented Kaggle preflight printing `/proc/meminfo` plus per-game action-tail lengths, which simultaneously settles the MAX_ACTIONS=2000 host-RAM assumption and quantifies the real cost of the dead early-stop flag. Refuted findings: 0.
