# V740 ARC outcome observer

Exp8624 adds optional observation records at the E3 policy and live agent wrapper.
The observer does not select actions, draw random numbers or change legacy
supervisor receipts. Installation requires an explicit call to
`E3AgentPolicy.install_arc_outcome_observer`.

A redirect window starts with its wrapper application action. It records up to120
distinct action outcomes. A complete window without level progress has status
`no_progress_within_horizon`. Reset, terminal, cutoff and missing support censor
unfinished windows. Identical duplicate deliveries add no support. A conflicting
duplicate censors a pending window. Overlapping redirects retain separate records
and name each other. Shared subsequent progress supplies no causal arm credit.

The legacy fields `resolved_by_levelup` and `actions_to_levelup` retain their old
meaning. New horizon statuses do not satisfy the old refinement gate.

The mechanical qualification uses navigation, toggle and sequence pixel streams.
Each class exercises a full horizon, early level progress, reset, terminal, cutoff,
missing observations, duplicate delivery, conflicting delivery and overlap.
Both branches use the actual `make_carnot_agent.choose_action` wrapper and E3
policy. Models and per-game adapters are disabled. The fixture uses a large depth
bound and distinct visible states so it can exercise a complete horizon.
Observer off/on actions, Python and NumPy RNG states, termination decisions and
original receipts must agree. These27 comparisons are development fixtures.
Their scripted levels are not public-game solves or independent science samples.

and V738 capstone. It checks original authority, transition and receipt hashes.

bytes, then decodes only uniquely located fields from their pinned pretty JSON.
