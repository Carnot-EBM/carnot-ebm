# Goal gradients for the live in-model ARC planner

Research and design only. No production change. The target is the first hidden-game level, with no win exemplar. The only task-specific inputs are the agent's induced `engine`, induced `is_level_complete`, and observed transitions.

## 1. Measured problem

`E3AgentPolicy._call_plan_in_model` passes a goal energy to `plan_in_model`. The default first-contact branch returns the same positive value for every non-goal grid (`python/carnot/agentic/arc_competition_agent.py:6326-6387`, `python/carnot/agentic/arc_competition_agent.py:6482-6496`). The planner orders its heap by that energy and then insertion order. Its `nodes_expanded` count is engine calls (`python/carnot/agentic/arc_executable_world_model.py:9486-9505`, `python/carnot/agentic/arc_executable_world_model.py:9512-9528`). This is breadth-first search on the flat part of the goal test.

Correct expert engines and completion tests have registered wins in 9 actions on sb26, 23 on dc22, and 33 on wa30. The expert tests were false on earlier route frames and true on the level-up frame (`docs/research-notes/gate-usefulness-2026-09-24.md:114-132`, `results/raw/experiment_10012_gate_usefulness/expert_predicate_validation.json:1-72`). Yet the live 20,000-call run found no plan on those three. sb26 needed 260,844 calls in the earlier unmasked search; wa30 had no goal at 400,000 calls (`docs/research-notes/gate-usefulness-2026-09-24.md:416-425`, `ops/known-issues.md:27699-27739`). A later non-live pruning branch needed 219,500 for sb26, still far beyond live budget; its no-op and equivalent-action pruning cut aggregate expert calls only 122,625→120,319 (2%) and kept wins at 5/10 (`ops/known-issues.md:27732-27739`; `deep-search` commit `cdc1d9d905`).

The scored wrapper uses `LIVE_SCORED`, a 20,000-call cap, and the live Stage-2 mask (`python/carnot/experiment_10013_planner_dedup_tiebreak.py:28-40`, `python/carnot/experiment_10013_planner_dedup_tiebreak.py:600-655`, `python/carnot/experiment_10013_planner_dedup_tiebreak.py:855-915`). In that harness, OFF won 5/10 expert windows. HUD dedup won 6/10 by adding dc22. The changed-pixel novelty tie-break also won 6/10, but lengthened existing winning plans in controls; it is not a safe default (`results/experiment_10013_planner_dedup_tiebreak.json:300-332`, `results/experiment_10013_planner_dedup_tiebreak.json:30873-31062`, `ops/known-issues.md:27717-27730`). sb26 has no live HUD mask, so dedup does not fix its plateau (`ops/known-issues.md:27725-27730`).

## 3. Candidate approaches

| Approach | Gradient without a win exemplar | Added cost per state | Main failure and length risk | Prior art |
|---|---|---|---|---|
| **A. Relax the induced goal and regress one terminal step.** Compile supported clauses of the model's own `is_level_complete` into distances: count unmet atoms, numeric inequality gaps, or minimum object-to-target assignment cost. If the goal only tests a post-win marker, inspect the induced engine's branch that creates that marker and score its guard. Use observed transitions to reject clauses that are constant, inconsistent, or depend on a HUD counter. Keep the original boolean test as the sole terminal check. | One pass through a bounded clause set and visible objects, roughly `O(P + F)`; small matching clauses cost `O(m³)` for `m` objects. Parse and guard extraction happen once per induced model. No extra engine call per node. | An induced predicate or engine may omit the true precursor, as the sb26 marker example shows (`results/raw/experiment_10012_gate_usefulness/experts_v2/sb26/expert_engine.py:165-170`, `results/raw/experiment_10012_gate_usefulness/experts_v2/sb26/expert_engine.py:187-189`). A greedy distance can take detours and yield a longer win. Unsupported clauses must stay flat. | [Bonet and Geffner, *Planning as Heuristic Search* (2001)](https://www.inf.ed.ac.uk/publications/report/1101.html); [Hoffmann and Nebel, *The FF Planning System* (2001)](https://arxiv.org/abs/1106.0675). |
| **B. Width novelty over observed facts.** Convert each visible transition to persistent facts, such as object color, position bin, pair relation, or action-effect signature. Prefer states that make a fact, or a small fact pair, true for the first time at a given depth and goal-distance bucket. This needs no positive goal example. It is different from the existing changed-pixel-from-start tie-break (`python/carnot/agentic/arc_executable_world_model.py:9435-9447`). | `O(F)` for singleton facts or `O(F²)` for pairs, with comparable fact-table memory. No extra engine call. | Novelty alone rewards irrelevant visual churn. Width two may cost too much. Pruning by width can lose a short path; best-first novelty can find a longer one. | [Lipovetzky and Geffner, *Width and Serialization of Classical Planning Problems* (2012)](https://nirlipo.github.io/publication/lipovetzky-2012-width/); [Lipovetzky and Geffner, *Best-First Width Search* (2017)](https://ojs.aaai.org/index.php/AAAI/article/view/11027). |
| **C. Guarded goal-distance BFWS.** Use A where its clauses vary on observed transitions. Use B only on flat distance plateaus. Rank by depth cost plus distance; break ties by new facts, then insertion order. Reserve a fixed share of calls for the unchanged FIFO frontier so a mistaken gradient cannot consume every call. The novelty table is conditioned on distance and depth, not raw changed-pixel count. | A's score plus singleton fact lookup per node. Pair facts are a separately budgeted ablation. No extra engine calls. | A wrong goal guard can still dominate. The FIFO reserve reduces that risk but can starve a 33-step route. `g+h` is not length-optimal when `h` is not admissible. Report actual plan length, not just wins. | BFWS combines a goal heuristic with novelty; LAMA shows why landmark and cost signals can complement each other ([Lipovetzky and Geffner 2017](https://ojs.aaai.org/index.php/AAAI/article/view/11027); [Richter and Westphal 2010](https://gki.informatik.uni-freiburg.de/papers/richter-westphal-jair10.pdf)). |

These are research candidates, not existing code paths. A boolean goal and pre-win transitions alone cannot identify a universally correct distance: sb26's predicate stays false until the marker appears (`results/raw/experiment_10012_gate_usefulness/experts_v2/sb26/expert_engine.py:187-189`). A and C require reading the agent's own induced engine source to regress such a marker through a generating guard. If that source is unavailable or the guard cannot be extracted safely, their goal score remains flat and B is the available search guide. Hindsight distance learning from a newly found win could help later levels, but it cannot guide the first hidden-game win without a terminal sample ([Andrychowicz et al., *Hindsight Experience Replay*, arXiv:1707.01495](https://arxiv.org/abs/1707.01495)).

## 5. Open questions

- Can a bounded parser find useful guards in *induced* marker-producing engines, or does it work only in the repaired sb26 expert? The expert guard is explicit, while its completion predicate exposes only a marker (`results/raw/experiment_10012_gate_usefulness/experts_v2/sb26/expert_engine.py:165-170`, `results/raw/experiment_10012_gate_usefulness/experts_v2/sb26/expert_engine.py:187-189`).
- Which observed facts are stable after HUD masking and model drift? The scored mask can be absent, notably on sb26 (`ops/known-issues.md:27725-27730`); the current planner's dedup key otherwise includes the full grid (`python/carnot/agentic/arc_executable_world_model.py:9423-9439`).
- Does the relaxed score rank *off-route* successors well enough to cut calls by an order of magnitude, while preserving the short plans? Route monotonicity alone cannot answer that.
- What FIFO reserve and depth penalty retain existing wins under one 20,000-call budget? The current novelty tie-break already showed longer control plans (`results/experiment_10013_planner_dedup_tiebreak.json:300-332`).
- How often is the model's own goal wrong or reachable only through an inaccurate transition? This scored test uses experts to isolate search; hidden-game performance still depends on induction quality (`docs/research-notes/gate-usefulness-2026-09-24.md:74-95`, `docs/research-notes/gate-usefulness-2026-09-24.md:114-132`).
## Induced-model check (2026-09-25)

I tested the section 4 extractor on the agent-written 10010 think-ON engines and the three 10009 codeonly first-shot engines per window. The scratch AST compiler accepts only pure `and`/`or`, equality, `>=`, `<=`, scalar counts, fixed tuple/set position equality, and a direct one-step marker-producing guard. It caps clauses and distance at 32. Unsupported code contributes zero distance. Parsing reads only the induced source; route labels, game IDs, expert code, and win frames enter only the later diagnostic replay. The two missing 10010 sources (dc22, ka59) are shown below but excluded from the THINK denominator. All 30 cached 10009 sources stay in the CODEONLY denominator, including invalid or incomplete code.

The probe used `rebuild_registered_trajectory` and logical real grids from the offline simulator. For ka59, the scratch replay passed the adapter’s registered click-payload resolver to `build_window_from_labels`, because the 10012 convenience wrapper omits it. Each induced predicate ran in a separate audited subprocess with a 30-second outer timeout and a 0.2-second per-grid timer. The extractor received no expert source. Observed variance uses the recorded visible window grids (`grid` plus each `next_grid`); route scores include the start and the real level-up frame. Exact scores, predicate truth values, source hashes, and full unsupported reasons are in `results/raw/goal_gradient_induced_check_2026_09_25/per_engine.json`.
