Background
----------

The conductor cycle (scripts/research_conductor.py, pick_next_task()) already checks
the exclusion manifest via _task_is_excluded() at the one guarded dequeue site.  This
is why retired experiments like Exp 527 and Exp 786 do NOT appear in the conductor's
own 11-experiment milestone cycle.

However, experiments also enter the "full-milestone queue" from unguarded historical
sources — scripts, batch runners, or queue files that call run_agent() or subprocess
the experiment scripts directly without going through pick_next_task().  These sites
do not call _task_is_excluded(), so the manifest is never consulted.

This is why Exp 786 (RETRO-028 closed .62) ran 77 min in both .63 and .64, and why
Exp 627 (RETRO-SYMCODE-SERIAL closed .64) ran 51 min unchanged in .64 despite the
implementation fix being deployed.

The Fix
-------

At EVERY site in scripts/research_conductor.py (and any other script) that can
dispatch or dequeue an experiment without going through pick_next_task(), add an
exclusion check BEFORE dispatching.

Step 1: Add a helper function near _task_is_excluded() (around line 832):

    def _exp_id_is_excluded(exp_id: int) -> tuple[bool, str]:
        """Return (is_excluded, reason) for a raw experiment ID.

        This is the companion to _task_is_excluded() for dispatch sites that hold
        an experiment ID rather than a full task dict.  Loads and queries the same
        conductor_exclusion_manifest.json file.

        Why this is needed: _task_is_excluded() requires a task dict (with 'title'
        and 'deliverable' fields from research-roadmap.yaml).  Unguarded dispatch
        sites often hold only an integer experiment ID, so we need a parallel check
        that operates on experiment IDs directly.
        """
        _ensure_exclusion_manifest_loaded()
        if _EXCLUSION_MANIFEST is None:
            return False, ""
        # The manifest stores excluded experiment IDs as integers under the key
        # "excluded_experiment_ids" (a list) or as string keys in "exclusions".
        # Check both formats for backwards compatibility.
        excluded_ids = _EXCLUSION_MANIFEST.get("excluded_experiment_ids", [])
        if exp_id in excluded_ids:
            reason = f"experiment_id={exp_id} in excluded_experiment_ids list"
            return True, reason
        # Also check the legacy dict format where each entry has an 'id' field.
        for entry in _EXCLUSION_MANIFEST.get("exclusions", []):
            if entry.get("id") == exp_id or entry.get("experiment_id") == exp_id:
                return True, entry.get("reason", "in exclusions list")
        return False, ""


Step 2: At every unguarded dispatch site, add the exclusion check before dispatching.

The pattern to apply (10–12 lines, applies to any site that dispatches by experiment ID):

    # --- MANIFEST ENFORCEMENT (apply at every unguarded dispatch site) ---
    excluded, excl_reason = _exp_id_is_excluded(exp_id)
    if excluded:
        logger.warning(
            "Skipping experiment %d — manifest exclusion: %s", exp_id, excl_reason
        )
        log_step(f"Exp {exp_id}", "SKIP", f"Excluded by manifest: {excl_reason}")
        continue  # or return, depending on the dispatch context
    # --- END MANIFEST ENFORCEMENT ---

Where to look for unguarded dispatch sites
------------------------------------------

Search scripts/research_conductor.py for:
  1. Any call to run_agent() that is NOT inside pick_next_task() or research_step().
  2. Any loop that iterates a list of experiment IDs (e.g., historical queue files,
     YAML lists, hardcoded experiment number ranges).
  3. Any call to subprocess or run_cmd() that invokes a scripts/experiment_*.py file
     by constructing a path from an experiment ID.
  4. The _archive_current_milestone() and _activate_next_roadmap() paths — if they
     re-queue tasks from research-complete.yaml without manifest filtering, previously
     retired experiments can re-enter the active queue on milestone rollover.

Additionally, audit any other scripts (batch_runner.py, queue_processor.py, or similar
if they exist) that dispatch experiment scripts without going through pick_next_task().
