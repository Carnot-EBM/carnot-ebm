Background
----------

pick_next_task() in research_conductor.py already checks the exclusion manifest
via _task_is_excluded() (Signal 3).  This is why the conductor cycle correctly
excludes retired experiments.  But unguarded historical queue sources dispatch
experiments without going through pick_next_task(), so the manifest is never
consulted at those sites.

Proof: Exp 786 (RETRO-028 closed .62) ran 77 min in both .63 and .64.
Exp 627 (RETRO-SYMCODE-SERIAL closed .64) ran 51 min unchanged in .64 despite
the implementation fix (Exp 841) being deployed.

The Fix
-------

Step 1: Add a helper function near _task_is_excluded() (around line 832):

    def _exp_id_is_excluded(exp_id: int) -> tuple[bool, str]:
        """Return (is_excluded, reason) for a raw experiment ID.

        Companion to _task_is_excluded() for dispatch sites that hold an
        integer experiment ID rather than a full task dict.
        """
        _ensure_exclusion_manifest_loaded()
        if _EXCLUSION_MANIFEST is None:
            return False, ''
        excluded_ids = _EXCLUSION_MANIFEST.get('excluded_experiment_ids', [])
        if exp_id in excluded_ids:
            return True, f'experiment_id={exp_id} in excluded_experiment_ids'
        for entry in _EXCLUSION_MANIFEST.get('exclusions', []):
            if entry.get('id') == exp_id or entry.get('experiment_id') == exp_id:
                return True, entry.get('reason', 'in exclusions list')
        return False, ''

Step 2: At every unguarded dispatch site, apply this 10-line pattern:

    excluded, excl_reason = _exp_id_is_excluded(exp_id)
